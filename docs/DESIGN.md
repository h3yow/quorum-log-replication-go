# Quorum Log Replication — 设计与验证说明

一套在本机多节点间运行的复制日志与领导者协调服务。用**本地文件**模拟持久化、
**进程内网络**模拟延迟 / 丢包 / 分区 / 节点崩溃，全程离线、零外部依赖。

## 1. 目录与职责

| 路径 | 职责 |
| --- | --- |
| `internal/raft/` | 共识核心：选举、日志复制、提交、领导租约、联合成员变更、快照与持久化 |
| `internal/simnet/` | 模拟网络：RPC 延迟/抖动、双向分区、黑洞丢包、节点上下线 |
| `internal/kv/` | 被复制状态机：确定性 Apply、`(ClientID,Seq)` 幂等去重、JSON 快照 |
| `internal/cluster/` | 本地编排：启动、崩溃/重启、分区、成员变更、线性一致读、只读观测 |
| `cmd/demo/` | 统一的本地启动与端到端验证入口 |
| `docs/` | 本文档 |

## 2. 一致性语义

- **多数派提交**：一条写入只有在当前配置的法定多数（联合期为 C_old、C_new
  双多数）持久化后才提交并对外可见；多数派不可达时不会产生新的提交。
- **同一任期唯一领导者**：结合选举安全（日志更新检查 + 一任一票）与
  **领导租约**（见 §4），同一领导权周期内不会出现两个可服务的领导者。
- **提交顺序一致**：所有节点以相同的日志下标顺序应用；`commitIndex`
  单调不减，绝不回滚已提交内容（Raft Log Matching / Leader Completeness）。
- **本任期提交约束（Figure 8）**：领导者上任先追加一条 no-op，只直接提交
  *本任期*条目；更早任期的条目随该 no-op 一起被间接提交，杜绝提交
  可能已被覆盖的旧日志。
- **线性一致读（ReadIndex）**：读请求先经一轮多数派心跳确认领导权，
  取当前 `commitIndex`，等待状态机应用到该位置后再返回本地数据；
  租约失效时拒绝并要求重定向，分区中的旧领导者不会返回过期读。
- **幂等客户端**：写入携带 `(ClientID, Seq)`。状态机记录每个客户端已见的
  最大序号，重复提交（超时重试、RPC 乱序导致的重复到达）只在第一次生效，
  后续返回成功但不重复应用；去重表进入快照，重启后依然成立。
- **冲突截断**：AppendEntries 任期不一致时按 Raft 规则截断冲突尾段，
  已提交内容因多数派持久化而不可能被不同任期覆盖。

## 3. 持久化与崩溃恢复（故障模型）

### 3.1 磁盘布局（节点数据目录，默认临时目录）

```
state.bin     HardState：term、vote、commitIndex（原子替换 + fsync 目录）
log.bin       段头(baseIndex/baseTerm) + 追加日志帧（每条 fsync）
snapshot.bin  状态机快照数据（原子替换）
snapmeta.bin  快照元数据（lastIndex/lastTerm/配置，带 CRC，原子替换）
```

所有记录帧为 `magic | type | len | payload | CRC32C`。

### 3.2 崩溃恢复保证

- 写入在**多数派 fsync 后**才确认；任一副本在任意时刻崩溃，已确认结果
  可由其余副本恢复，重启节点经快照 + 增量日志追齐。
- `term/vote` 先持久化再投票，`commitIndex` 随 HardState 落盘，
  因此无快照重启也不会丢失提交下界、不会在同一任期投两票。
- **可区分的拒绝原因**（不以不确定状态继续服务）：
  - 尾部记录不完整（写入中途掉电/截断）→ `ErrTruncatedStorage`；
  - 魔数不符 / 长度非法 / CRC 不符 / 日志不连续或任期回退
    → `ErrCorruptStorage`；
  - 快照落后于现存状态 → `ErrSnapshotBehind`；
  - 请求下标超出快照覆盖的日志范围 → `ErrGap`。

  集群层 `Restart` 原样向上返回这些错误，调用方可据此区分处理。
- 快照安装分"数据→元数据（提交点）→日志段抬升"三步，崩溃在中间态时
  重启以已可见的快照为准对账（`reconcile`），不产生空洞。

## 4. 领导选举与故障切换

- 节点角色 `follower / candidate / leader`，由**唯一事件循环 goroutine**
  串行处理所有输入（提案、RPC、定时器），内部可变状态无锁、无数据竞争。
- 选举超时在 `[ElectionMin, ElectionMax]` ticks 内随机；集群为每个成员
  使用独立 ticker 且相位错开，降低同拍平票概率；平票后随机退避重试。
- 候选人日志必须"至少一样新"（比较最后任期、最后下标）才能获票。
- **领导租约（滑动窗口）**：领导者记录每个选民最近一次心跳确认的 tick。
  窗口严格小于跟随者最小选举超时：
  - 窗口内仍有多数派确认 → 租约有效，可服务提案与读；
  - 多数派不可达 → 一个选举超时内租约失效，立即以 `ErrNoQuorum`
    拒绝新提案/读，而不是无限挂起；
  - 当选时把授票者播种为已确认（它们授票时都已重置选举定时器），
    给首批心跳往返留出初始窗口；领导者自身每拍自我确认。
- 旧领导者收到更高任期 RPC 立即退回 follower，并以
  `ErrLeadershipLost` 通知其挂起提案；客户端凭幂等键重试到新领导者。

## 5. 动态成员变更（联合共识）

采用两阶段联合共识，保证变更过程中已提交数据不丢、不错位：

```
C_old ── Conf 条目(Voters=C_old, Joint=C_new) 已提交 ──▶ 联合期
      ── Conf 条目(Voters=C_new, Joint=nil)   已提交 ──▶ C_new
```

规则与判定：

- **未提交不算数**：联合期的提交与选举都要求 C_old、C_new **双多数**；
  配置只有在对应日志条目*提交*后才更新 `committedConfig`（投票/快照依据）。
  条目仅在*追加*后进入复制集合 `config`（决定向谁推日志）。
- **新节点先追赶后获权**：新节点以普通进程启动，领导者先提交一条
  `EntryAddNonVoter` 预告条目，立即对其推送 InstallSnapshot + 增量日志；
  待其追平后才进入联合配置获得投票权，避免新的空日志节点拖垮可用性。
- **变更串行**：上一次联合变更未落到普通配置时，拒绝新的变更
  （`ErrJointChangeInProgress`）。
- **幂等续接**：变更中途领导权易主时，调用方可安全重试；`ChangeConfig`
  检测目标联合/最终配置是否已在日志中，从对应阶段续接，不重复造条目。
- **移除自己**：领导者被最终配置移除时，先成功通知该配置提案，
  再交出领导权（由新配置下的选举接管），避免把已提交变更误报为失败。
- 目标配置不能为空，且与旧配置必须有交集（禁止单步替换全部投票成员）；
  违反则 `ErrInvalidConfig`。

## 6. 日志压缩与落后节点追赶

- 已应用日志条数超过 `SnapshotThreshold` 时生成状态机快照
  （含 KV 数据、去重表、applied 下标、**已提交配置**），并原子截断旧日志。
- 快照只冻结**已提交配置**，未稳定的联合配置绝不会进入快照。
- follower 所需位置被领导者快照覆盖时，自动改发 InstallSnapshot：
  follower 经 `InstallRemoteSnapshot`（不要求快照点存在于本地日志）
  直接跳到快照点，随后由 AppendEntries 增量补齐——压缩/清理期间
  无数据空洞，也不回滚已提交内容。

## 7. 只读观测（不影响集群行为）

- 节点 `Status()` / 集群 `Status()` 返回深拷贝快照：成员、角色、任期、
  领导权归属、commit/last/applied 下标，以及领导者视角各节点
  `nextIndex/matchIndex` 同步进度。纯内存读取，不发任何 RPC、不改状态。

## 8. 模拟的故障模型（simnet）

- `Register/Unregister`：节点上线 / 崩溃（入站失败、出站被拒）；
  分区关系在重启后仍保留。
- `AddPartition/RemovePartition/HealAll`：链路对级别的双向网络分区。
- `SetDrop`：出向黑洞（请求挂起直到超时），用于构造超时重试/乱序。
- 每次 RPC 带基础延迟 + 随机抖动，所有投递在调用前再次校验链路状态，
  因此"等待期间发生分区/崩溃"也能被正确模拟。

## 9. 本地验证方法（完全离线）

要求 Go 1.25+，无需任何外部服务、网络或凭据。

```bash
# 1) 单元 + 异常链路测试（分区/重启/重复请求/并发变更/损坏恢复）
go test ./... -count=1
go test ./internal/cluster/ -race -count=3     # 竞态检测 + 重复
go test ./internal/raft/ -v                    # 存储 CRC/截断/快照/多数派

# 2) 统一的端到端验证入口（选举/写入/崩溃重启/分区/幂等/
#    并发写入/成员变更扩缩容/快照追赶/只读观测）
go run ./cmd/demo                     # 临时目录，结束即清理
go run ./cmd/demo -dir ./run -keep   # 保留现场数据便于检查磁盘文件
```

`cmd/demo` 依次断言：多数派分区期间可写、少数派写入被拒绝、
分区恢复后历史对齐、重复请求只生效一次、并发写入最终一致、
扩缩容期间已提交数据不丢、长期离线节点经快照追平。

## 10. 关键参数（`raft.Options`，可按机器速度调整）

| 参数 | 含义 | 默认（tick=10ms） |
| --- | --- | --- |
| `ElectionMinTicks/MaxTicks` | 随机选举超时范围 | 10 / 20 ticks |
| `HeartbeatTicks` | 心跳周期 | 2 ticks |
| `SnapshotThreshold` | 触发快照的日志条数 | 100（demo 用 20 演示追赶） |
| `RPCTimeout` | 单次 RPC 超时 | 100ms（快照 4×） |

状态转换日志统一带判定依据（如 `grant vote ...`、`lease expired ...`、
`config committed ...`、`conflict, backoff nextIndex=...`），
便于解释每一次选举、提交与成员变更的决策过程。
